## DELETE maintenance protection

`delete_maintenance.py snapshot a3` returns infrastructure-only sandbox IDs/states and active-job counts. After making a node unschedulable, `enter a3 --state-file /private/path/lease.json --ids-file /private/path/ids.json --ttl 300` acquires an owner-scoped preparation lease and waits on ordered sandbox row locks. It aborts if any protected ID already changed runner or desired state. It never changes sandbox rows. Confirm complete IDs and jobs=0 again after entry.

Before stopping any real inner container, `latch a3 --state-file ...` changes only the same owner's lease to persistent. This prevents a crashed coordinator from silently losing protection. During rollout, inspect `status` and stop normal actions if ownership is lost. The coordinator has a 600-second maintenance deadline and initiates rollback on timeout; it does not release the lease on failure. Only after candidate OR rollback health, fresh API health, and exact container ID checks succeed may the coordinator call `release`. Do not blindly release a latched lease. Root private state files contain owner tokens; stdout exposes only their hash. The helper has no public HTTP endpoint.

DELETE checks the runner lease before validation and again inside the existing `FOR UPDATE` transaction before any mutation. Only Redis PTTL=-2 allows deletion; persistent keys, Redis failure or a two-second lookup timeout return HTTP503 with Retry-After. DESTROYED remains emitted only after the transaction commits. This guard protects DELETE, not the entire lifecycle state machine; unschedulable alone and paused job polling cannot prevent DELETE from removing backups. Existing GET/exec/status and other nodes are unchanged when Redis is healthy and no lease is present.

Regression tests use actual service/repository/controller methods, isolated PostgreSQL row locks, real Redis TTL/PERSIST/owner compare operations and actual Nest HTTP requests. Both orderings are covered: delayed DELETE is rejected after gate entry; a DELETE which already passed its locked check completes first and makes the entry barrier abort. Tests never send DELETE to production.
