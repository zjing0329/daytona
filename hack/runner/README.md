# Complete Runner build

Runner requires both daemon-amd64 and daytona-computer-use in its embedded filesystem. The daemon also embeds terminal HTML, xterm.js 5.3.0, xterm.css, the 0.8.0 fit addon, the recording dashboard, matplotlib_wrapper.py and repl_worker.py. The HTML and Python resources are tracked source files; daemon:prepare downloads the three pinned terminal assets.

Use SOURCE_REVISION=<reviewed-commit> VERSION=<reviewed-version> bash hack/runner/build-complete-amd64.sh in an isolated copy with Go, Python 3 and the computer-use X11 build libraries. This runs the dependency steps from apps/runner/project.json, builds an Alpine-compatible CGO_ENABLED=0 Runner and daemon, validates the two embedded ELF files, and emits dist/runner-assets.sha256. Computer-use retains its required CGO/X11 support. Do not replace the complete build with go build on Runner alone.

Before publishing or rolling production, start the final runtime image with its real entrypoint, dummy credentials, an isolated network and a fresh disposable Docker data volume. Require inner docker info, Runner HTTP health, both extracted assets matching the manifest, zero restarts and no unexpected containers. A --help/config-only check does not validate asset extraction or startup. Never mount an existing Runner's Docker volume for this test.

Package with `python3 hack/runner/package-complete-image.py --source-root <clean-checkout> --workspace <complete-build-directory> --source-revision <40-character-commit> --base-image <existing-runtime-image> --expected-base-image-id sha256:<64-character-id> --tag <new-candidate-tag> --output <new-packaging-manifest.json>`. This verifies source inputs against the clean commit, all six asset hashes and ELF resources, the immutable base image, and unchanged runtime configuration. The Dockerfile requires valid provenance and verifies the copied Runner hash. Packaging does not deploy or replace an existing container.

Then run `python3 hack/runner/smoke-complete-image.py --image <new-candidate-tag> --manifest <complete-build-directory>/dist/runner-assets.sha256 --output <new-smoke-directory>`. The fake API rejects invalid recovery page sizes and the real Runner must use page size 100. Keep the packaging and smoke manifests together; packaging alone is not a startup test.

The build starts by removing old generated outputs and recording all build inputs, workspace module manifests, recipe hashes and the effective Go toolchain. It verifies the inputs again after compilation and writes `dist/build-receipt.json`. Packaging requires that receipt and rejects old outputs/receipts paired with new source, or extra build inputs. Keep the original checkout clean and use its complete `go.work`; a reduced test workspace is not a release build. This prevents accidental provenance mixing, rather than claiming protection against a malicious local build operator.
